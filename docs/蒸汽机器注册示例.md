# 蒸汽机器注册示例

> 基于 `dev.celestiacraft.cmi.api.mbd2.steam` 包 (MB2 蒸汽机器体系)。

## 完整实例 (可直接粘贴到 CMICore)

一台单方块 (蒸汽压机) + 一台多方块 (蒸汽炉) + 两种蒸汽输入总线 + 各自配方:

```java
package dev.celestiacraft.cmi.mbd2;

import com.lowdragmc.mbd2.api.pattern.FactoryBlockPattern;
import com.lowdragmc.mbd2.api.pattern.Predicates;
import com.lowdragmc.mbd2.api.recipe.MBDRecipeType;
import com.lowdragmc.mbd2.api.registry.MBDRegistries;
import com.lowdragmc.mbd2.common.event.MBDRegistryEvent;
import dev.celestiacraft.cmi.Cmi;
import dev.celestiacraft.cmi.api.mbd2.steam.AbstractSteamMachine;
import dev.celestiacraft.cmi.api.mbd2.steam.MultiBlockSteamMachine;
import dev.celestiacraft.cmi.api.mbd2.steam.SingleSteamMachine;
import dev.celestiacraft.cmi.api.mbd2.steam.SteamInputBus;
import dev.celestiacraft.cmi.api.mbd2.steam.SteamRegistry;
import net.minecraft.resources.ResourceLocation;
import net.minecraft.world.item.ItemStack;
import net.minecraft.world.item.Items;
import net.minecraft.world.level.block.Blocks;
import net.minecraftforge.eventbus.api.SubscribeEvent;
import net.minecraftforge.fml.common.Mod;
import net.minecraftforge.registries.ForgeRegistries;

@Mod.EventBusSubscriber(modid = Cmi.MODID, bus = Mod.EventBusSubscriber.Bus.MOD)
public class SteamMachinesExample {
	// ==================== 机器注册 ====================
	@SubscribeEvent
	public static void registerMachines(MBDRegistryEvent.Machine event) {
		// ① 单方块: 蒸汽压机 (默认消耗 2 mB/tick)
		event.register(new SingleSteamMachine(Cmi.loadResource("steam_press"))
				.recipeType(Cmi.loadResource("steam_press_rt"))
				.steamCapacity(16000)
				.steamPerTick(2)
				.model(Cmi.loadResource("block/machine/steam_press/off"),
						Cmi.loadResource("block/machine/steam_press/on"))
				.build());

		// ② 多方块: 蒸汽炉 (3x3x3 固定结构, 默认消耗 4 mB/tick)
		event.register(new MultiBlockSteamMachine(Cmi.loadResource("steam_oven"))
				.recipeType(Cmi.loadResource("steam_oven_rt"))
				.steamPerTick(4)   // 多方块无 steamCapacity: 蒸汽仓 = 结构里的输入总线, 容量由总线等级决定
				.model(Cmi.loadResource("block/machine/steam_oven/off"),
						Cmi.loadResource("block/machine/steam_oven/on"))
				.pattern(() -> FactoryBlockPattern.start()   // Supplier 惰性构建: 总线方块注册晚于本事件
						.aisle("IBI", "I I", "III")   // y=0: 前面中心放输入总线
						.aisle("I I", "IAI", "I I")   // y=1: 中空
						.aisle("III", "ICI", "III")   // y=2: 顶部中心控制器
						.where('I', Predicates.blocks(Blocks.IRON_BLOCK))
						.where('B', Predicates.blocks(block("cmi:bronze_steam_input_bus"))
								.or(Predicates.blocks(block("cmi:steel_steam_input_bus"))))
						.where('A', Predicates.air())
						.where('C', Predicates.controller(Predicates.any()))
						.build())
				.build());

		// ③ 蒸汽输入总线 (GT 风格: 功能一样, 容量 = 等级)
		event.register(SteamInputBus.build(Cmi.loadResource("bronze_steam_input_bus"),
				"cmi:block/machine/io/bronze_steam_input", 4000));
		event.register(SteamInputBus.build(Cmi.loadResource("steel_steam_input_bus"),
				"cmi:block/machine/io/steel_steam_input", 16000));
	}

	// ==================== 配方类型 + 配方 ====================

	@SubscribeEvent
	public static void registerRecipeTypes(MBDRegistryEvent.MBDRecipeType event) {
		// 一行: 为上面所有蒸汽机器注册各自的配方类型 (专业对口)
		SteamRegistry.registerRecipeTypes(event);

		// ① 蒸汽压机配方: 不写 steam_per_tick -> 沿用机器默认 2 mB/tick
		MBDRecipeType press = MBDRegistries.RECIPE_TYPES.get(Cmi.loadResource("steam_press_rt"));
		press.recipeBuilder(Cmi.loadResource("press_iron_plate"))
				.duration(200)
				.inputItems(Items.IRON_INGOT)
				.outputItems(new ItemStack(Items.IRON_BLOCK))
				.saveAsBuiltinRecipe();

		// ② 蒸汽炉配方: 覆盖本配方消耗为 8 mB/tick
		MBDRecipeType oven = MBDRegistries.RECIPE_TYPES.get(Cmi.loadResource("steam_oven_rt"));
		oven.recipeBuilder(Cmi.loadResource("bake_stone"))
				.duration(100)
				.inputItems(Items.COBBLESTONE)
				.outputItems(new ItemStack(Items.STONE))
				.addData(AbstractSteamMachine.STEAM_PER_TICK_KEY, 8)
				.saveAsBuiltinRecipe();
	}

	private static Block block(String id) {
		return ForgeRegistries.BLOCKS.getValue(ResourceLocation.fromNamespaceAndPath(id));
	}
}
```

> 注: 示例机器 id (`steam_press`/`steam_oven`/`*_steam_input_bus`) 和模型路径
> (`cmi:block/machine/...`) 是占位, 换成你自己的。多方块示例结构是 3x3x3
> (铁块壳 + 中空 + 前脸输入总线 + 顶部控制器), 按需改 aisle。

## 类速览

| 类                        | 职责                                                                                  |
|---------------------------|---------------------------------------------------------------------------------------|
| `AbstractSteamMachine<M>` | 抽象父类: 蒸汽槽 trait / 状态树 base→working/suspend / 运行时抽取与暂停恢复 / 标准 UI |
| `SingleSteamMachine`      | 单方块蒸汽机器                                                                        |
| `MultiBlockSteamMachine`  | 多方块蒸汽机器 (固定结构, pattern 由调用方传)                                         |
| `SteamInputBus`           | 蒸汽输入总线部件 (容量分级 = GT 多等级总线)                                           |
| `SteamRegistry`           | 机器登记 + 配方类型自动注册 + 事件分发                                                |
| `UISpec`                  | 机器 GUI 链式 DSL                                                                     |

## 消耗语义速记

```
工作期间每个 tick:
    蒸汽槽 >= 本 tick 消耗  ->  抽走, 继续工作
    蒸汽槽不足             ->  配方暂停 (SUSPEND) + 机器切 suspend 状态

蒸汽恢复:
    suspend 状态下蒸汽槽 >= 默认消耗  ->  自动继续工作 (WORKING + working 状态)
```

- 本 tick 消耗 = 配方 `data.steam_per_tick` (有) 或机器 `steamPerTick` (默认)。
- 蒸汽只认 `forge:steam` tag 流体 (`CmiFluidTags.STEAM`)。
- 蒸汽源: 单方块 = 自身蒸汽槽 (`steamCapacity` 参数), 管道直接贴机器泵蒸汽即可
  (槽六面全 IN, 不需要输入总线); 多方块 = 成型结构中所有输入总线的蒸汽仓
  (无 `steamCapacity`, 容量由总线等级决定)。
- 蒸汽数据存槽里, MB2 持久化; 父类实例无状态, 按机器定义 id 查表分发。

## 蒸汽输入总线 (完整用法)

GT 风格多等级: 功能一样, 容量不一样。加新等级 = 再加一行:

```java
@SubscribeEvent
public static void registerMachines(MBDRegistryEvent.Machine event) {
    // 青铜 / 钢 / 钛 三档 (容量递增)
    event.register(SteamInputBus.build(Cmi.loadResource("bronze_steam_input_bus"),
            "cmi:block/machine/io/bronze_steam_input", 4000));
    event.register(SteamInputBus.build(Cmi.loadResource("steel_steam_input_bus"),
            "cmi:block/machine/io/steel_steam_input", 16000));
    event.register(SteamInputBus.build(Cmi.loadResource("titanium_steam_input_bus"),
            "cmi:block/machine/io/titanium_steam_input", 64000));
}
```

放进多方块结构 (槽位谓词, 惰性 pattern 里引用):

```java
.pattern(() -> FactoryBlockPattern.start()
        .aisle("IBI", "I I", "III")
        .aisle("I I", "IAI", "I I")
        .aisle("III", "ICI", "III")
        .where('I', Predicates.blocks(Blocks.IRON_BLOCK))
        .where('B', Predicates.blocks(block("cmi:bronze_steam_input_bus"))
                .or(Predicates.blocks(block("cmi:steel_steam_input_bus")))
                .or(Predicates.blocks(block("cmi:titanium_steam_input_bus"))))
        .where('A', Predicates.air())
        .where('C', Predicates.controller(Predicates.any()))
        .build())
```

总线工作方式 (GT 蒸汽仓模型):

- 总线 = 多方块的蒸汽仓: 自带蒸汽槽 (`name="steam"`), 容量 = 等级构造参数。
- 外部管道接总线任意面泵蒸汽 (`forge:steam` tag 内任意流体) -> 存入总线蒸汽槽。
- 多方块工作时从成型结构中**所有**总线的蒸汽槽并联抽取 (控制器无蒸汽槽,
  `findSteamStorages` 遍历部件聚合)。
- 放进 N 个钢总线 = 蒸汽仓 N x 16000 mB; 拆掉总线则结构失效, 蒸汽跟着总线走。
- 需要更多等级: 只加模型文件 + 一行 build 调用。

## 自定义 UI

### 零代码: 标准 UI 已内置

父类自动注入: 标题 + 蒸汽水位条 + 配方进度条 + 物品槽自动两列排布 (IN 左 / OUT 右) +
蒸汽槽固定在右侧。不需要写任何 UI 代码。

### 自定义: 覆盖 createStandardUI + UISpec 链式 DSL

```java
public final class SteamPress extends SingleSteamMachine {

    public SteamPress(ResourceLocation id) {
        super(id);
    }

    @Override
    protected WidgetGroup createStandardUI(MBDMachine machine) {
        return UISpec.create(machine, 176, 166, ui -> ui
                .background("cmi:textures/gui/steam_press.png")   // 自定义背景
                .title(70, 5)                                     // 机器名 (MB2 自动填文本)
                .steamBar(60, 20, 18, 52)                          // 蒸汽水位条
                .progressBar(79, 42)                               // 配方进度
                .slot("input", 40, 42)                             // trait 名自动绑 storage
                .slot("output", 114, 42)
                .tank(STEAM_TRAIT_NAME, 141, 22, 18, 58)           // 蒸汽槽 (父类常量 "steam")
                .button(78, 66, 18, 18, click -> {
                    // ClickData: click.button / click.isRemote...
                    System.out.println("clicked");
                })
                .image(8, 8, 16, 16, "cmi:textures/gui/icon.png") // 装饰贴图
                .widget(customWidget));                            // 任意 LDLib Widget
    }
}
```

UISpec 方法速查:

| 方法 | 说明 |
|---|---|
| `background(path)` | 整体背景贴图 |
| `title(x, y)` | 机器名标题 (文本自动填) |
| `slot(trait名, x, y)` / `(x, y, w, h)` | 物品槽, 按 trait 名自动绑 storage |
| `tank(trait名, x, y, w, h)` | 流体槽, 自动绑 storages[0] |
| `progressBar(x, y)` / `(x, y, w, h)` | 配方进度 (自动 getProgressPercent) |
| `steamBar(x, y, w, h)` | 蒸汽水位条 (默认读 "steam" trait, 可指定其它槽名) |
| `button(x, y, w, h, click -> ...)` | 按钮 (ClickData 回调) |
| `image(x, y, w, h, path)` | 装饰贴图 |
| `widget(Widget)` | 任意 LDLib Widget |

规则: 引用不存在的 trait 名会直接抛异常 (带机器 id 和名字); 坐标即像素位置, 手动排布。

### UI 是怎么被引用的 (链路说明)

自定义 UI **不需要手动注册**, 链路是:

```
子类覆盖 createStandardUI(machine)
        │  (虚方法分发)
        ▼
父类 build() -> injectUI(definition)
        │  把 this::createStandardUI 反射注入机器的 uiCreator
        ▼
玩家打开 GUI -> MB2 调 uiCreator.apply(machine) -> 你的 WidgetGroup 显示出来
```

所以注册处直接用你的子类替换 `SingleSteamMachine` 即可, 其余链式不变:

```java
event.register(new SteamPress(Cmi.loadResource("steam_press"))
        .recipeType(Cmi.loadResource("steam_press_rt"))
        .steamCapacity(16000)
        .steamPerTick(2)
        .model(Cmi.loadResource("block/machine/steam_press/off"),
                Cmi.loadResource("block/machine/steam_press/on"))
        .build());   // build() 里自动注入你覆盖的 createStandardUI
```

- `injectUI` 是 protected: 不需要 UI 的机器可以覆盖它留空。
- 多方块同理: `class SteamOven extends MultiBlockSteamMachine` 覆盖 createStandardUI。

### 运行时改 UI (MachineUIEvent, 可选)

```java
@SubscribeEvent
public static void onMachineUI(MachineUIEvent event) {
    event.getRoot().addWidget(new ImageWidget(80, 5, 16, 16,
            new ResourceTexture("cmi:textures/gui/my_icon.png")));
    // 或整体替换: event.setRoot(myGroup);
}
```

## 自定义扩展

```java
// 1) 加物品/流体槽: 子类覆盖 createSettings() 追加 traitDefinitions
```

## 模型要求

- 模型放 CMICore `resources/assets/cmi/models/block/...` 或整合包 kubejs 资产 (GenMBDModel 生成)。
- 状态模型: `base`=off, `working`=on, `suspend` 不传则继承 base。
- 标准 UI 已内置 (标题/蒸汽条/进度条/蒸汽槽/物品槽自动排布), 零 UI 代码可跑。
